## 1. zApkStart ב-30 שניות

```
קיצור דרך בשולחן העבודה (סמל יישום אמיתי ‎.lnk‎)
      │ לחיצה כפולה
      ▼
zApkStart.exe --launch <חבילה>
      │ סביבת הריצה לא פועלת? → מופעלת אוטומטית (אמולטור Android 14, מובנה או נשמר בהורדה ראשונה)
      ▼
היישום נפתח דרך נקודת הכניסה שהמערכת מזהה (לא ה-Activity הראשי הכתוב קשיח בתוך ה-APK)
      ▼
חלון האמולטור = חלון היישום (כותרת מותאמת, סמל משלו, יחס אנכי, מסך מלא במרכז)
```

**מה מייחד אותו**

- 🖱️ **לחיצה כפולה על ‎.apk‎ מתקינה**: אחרי רישום שיוך הקבצים, לחיצה כפולה על קובץ APK → ניתוח אוטומטי → התקנה → יצירת סמל בשולחן העבודה.
- 🧩 **סמל שולחן עבודה לכל יישום**: הסמל מחולץ אופליין מתוך ה-APK עצמו; לחיצה כפולה על הסמל נכנסת ישר ליישום.
- 🪟 **יישום הוא פשוט חלון**: רינדור מקורי, במסך מלא ממלא את גובה המסך ומתמקד, במצב חלון אפשר לגרור ולשנות גודל, וכל יישום זוכר את הגודל שלו.
- 🔍 **נמצא דרך החיפוש של Windows**: קיצורי דרך כפולים בשולחן העבודה ובתפריט התחל (`Programs\zApkStart\`).
- 📁 **נתונים משותפים**: `%USERPROFILE%\zApkStartShared` ↔ ‎`/sdcard/zApkStartShared`‎ באנדרואיד, בסנכרון דו-כיווני.
- 🪶 **מגיע עם סביבת ריצה משלו**: לא תלוי באמולטור שמותקן אצלכם — לא MuMu / LDPlayer / WSA.

> הערה: זהו פרויקט קוד פתוח בשלב מוקדם, חינמי וללא פרסומות, המתוחזק בזמנו הפנוי. תקלות הן דבר צפוי — בשביל זה בדיוק נכתב המדריך הזה.

## 2. התקנה והפעלה ראשונה

### 2.1 בחירת הגרסה המתאימה לך

zApkStart מופץ מההפצות שלו ב-GitHub בלבד — הוא אף פעם לא מוריד גרסאות מהפרויקט המקורי ApkStart:

- GitHub: `github.com/zeevrussak/zApkStart/releases`

| גרסה | קובץ | מתי בוחרים בה |
|---|---|---|
| **גרסת חנות (MSIX)** | `zApkStart_<ארבעה מספרים>_x64.msix` | התקנה מרשימת Microsoft Store. כוללת סביבת ריצה מלאה, עובדת אופליין אחרי ההתקנה, והעדכונים מנוהלים על ידי החנות |
| **נייד מלא** | `zApkStart-v*-win64-full.zip`‏ (‎~830 MB‎, ‎~1.3 GB‎ לאחר חילוץ) | לא רוצים להתקין ולא לחכות להורדות: מחלצים ומריצים, סביבת הריצה בתוך החבילה |
| **התקנה** | `zApkStart-v*-Setup.exe`‏ (‎~1.3 GB‎) | רוצים קיצורי דרך בשולחן העבודה/תפריט התחל ורשומת הסרה |
| **נייד קל** | `zApkStart-v*-win64-portable.zip`‏ (‎96 MiB‎, ‎~227 MB‎ לאחר חילוץ) | רוצים קודם לנסות; סביבת הריצה מורידה בהפעלה הראשונה |
| **נייד קל ARM64** | `zApkStart-v*-arm64-portable.zip` | מחשבי Windows על ARM64 — ראו [Windows ARM64](#arm64) להלן |

> ⚠️ **השתמשו תמיד בגרסה החדשה ביותר (כרגע 0.6.4)**. גרסאות ישנות (0.5.x ומטה) או לא כללו סביבת ריצה מובנית (כל הפעלה חיפשה/הורידה 1.5 GB של סביבת ריצה), או שהשתמשו כברירת מחדל בחלון מוטמע — המקור הקלאסי ל"איטי מאוד, לא נפתח, נפתח חלון עם כפתור מסתובב". אם אתם משדרגים מגרסה ישנה, ודאו שקיצור הדרך בשולחן העבודה מצביע על תיקיית התוכנה החדשה.

### 2.2 מה קורה בהפעלה הראשונה

1. **(נייד קל בלבד) הורדת סביבת הריצה**: adb, Android Emulator ותמונת המערכת של Android 14; המקורות הרשמיים מגיעים ל-10+ MB/s עם הורדה מקבילית ב-8 חוטים + המשך מנקודת עצירה. גרסאות מלא/חנות מדלגות על השלב.
2. **חילוץ ראשון של התמונה**: תמונת ה-xz נחלצת אל ‎`%APPDATA%\zapkstart\system-images`‎ (כ-20 שניות, פעם אחת בלבד).
3. **יצירת ‎`/data`‎ ראשונה**: zApkStart יוצר בעצמו נתוני משתמש ext4 עם הצפנה ותוויות SELinux (בתמונה הרשמית יש רק דוגמה של 1 MB).
4. **אתחול אוטומטי**: מכאן והלאה הפעלת יישום היא `am start` אחד; אתחול קר לוקח כ-23 שניות ושחזור מ-snapshot כ-10 שניות.

> הפעלה ראשונה איטית זה תקין — זו עלות חד-פעמית. מהפעלה הבאה והלאה הכניסה מיידית.

## 3. שימוש יומיומי

### 3.1 התקנת יישומים

שלוש דרכים, לבחירתכם:

- **לחיצה כפולה על קובץ ה-APK** (קודם לרשום את השיוך: הגדרות → שילוב מערכת → שיוך קבצי ‎.apk‎);
- "התקנת יישום" בחלון הראשי;
- שורת פקודה: `zApkStart.exe <נתיב\to.apk>`.

חבילות מפוצלות (‎`.apks`‎ / ‎`.xapk`‎) נתמכות (באמצעות `install-multiple` אוטומטית). קיצורי דרך בשולחן העבודה ובתפריט התחל נוצרים אוטומטית אחרי ההתקנה.

### 3.2 פתיחת יישומים

פשוט לחצו לחיצה כפולה על הסמל בשולחן העבודה. כל היישומים חולקים סביבת ריצה אחת, ולכן **היישום השני נפתח כמעט מיד**.

### 3.3 חלונות ותצוגה

| פעולה | איך |
|---|---|
| מסך מלא / חלון | ‏`F11` או תפריט ימני במגש המערכת. מסך מלא רק מגדיל את החלון, לא משנה את יחס התמונה |
| סיבוב אנכי/אופקי | ‏`Ctrl+Alt+R` (גלובלי) או כפתור הסיבוב בשורת הכותרת; הכיוון נזכר לכל יישום |
| מסך מלא אוטומטי | הגדרות → תצוגה וחלונות → מסך מלא אוטומטי (הכי טוב בשילוב עם "כיוון מאולץ") |
| אופקי/אנכי בכפייה | הגדרות → תצוגה וחלונות → כיוון המסך |

> רק המעבר האחד שבו "כיוון הפאנל שונה מכיוון היישום" מפעיל מחדש את סביבת הריצה (כ-40 שניות, שורת הכותרת מציגה הודעה). יישומים באותו כיוון נפתחים מיד אחריהם.

### 3.4 קיצורי מקלדת

| מקשים | אפקט |
|---|---|
| `F11` | מעבר בין מסך מלא למצב חלון |
| `Ctrl+Alt+R` | סיבוב היישום הנוכחי אנכי/אופקי |
| `Ctrl+R` | סיבוב בתוך חלון המעטפת (במצב חלון מקורי השתמשו ב-`Ctrl+Alt+R`) |

### 3.5 החלפת קבצים (Windows ↔ Android)

‏`%USERPROFILE%\zApkStartShared` במחשב ו-‎`/sdcard/zApkStartShared`‎ בתוך אנדרואיד מסתנכרנים דו-כיוונית תוך שניות.
נקודת כניסה: הגדרות → שילוב וקבצים → החלפת קבצים ("סנכרון מיידי" או "פתיחת התיקייה").

### 3.6 ניווט במסך ההגדרות

מגרסה 0.6.0 ההגדרות מחולקות לשמונה קטגוריות עם תיבת חיפוש בראש המסך (הקלידו מילות מפתח כמו "אופקי", "זיכרון", "מתאם" — חיפוש חוצה קטגוריות):

| קטגוריה | תוכן עיקרי |
|---|---|
| כללי והתקנה | סביבת ריצה וסביבה, הגדרה בלחיצה אחת, הפעלה עם האתחול, שימוש בדיסק וניקוי |
| תצוגה וחלונות | מצב תצוגה, מסך מלא אוטומטי, כיוון מסך, פריסת טאבלט, אחסון חלונות |
| קלט ופקדים | כפתורי עכבר, מיפוי מקלדת |
| ביצועים ומשאבים | מדיניות משאבים, העדפת מאיץ גרפי (ייעודי/מובנה), מיקרופון, איכות תמונה, מחיצת נתונים, שפת המערכת, snapshots, חימום מקדים באתחול |
| רשת והורדות | עדכונים ומקורות הורדה, מראות מואצות, מספר חוטי הורדה, DNS מהיר |
| אבחון ותיקון | בדיקת מצב של המחשב, טלאי מנהל/תאימות, זיהוי אוטומטי |
| שילוב וקבצים | שולחן עבודה ויישומים, החלפת קבצים, שילוב מערכת |
| עדכונים ואודות | עדכוני תוכנה, אודות |
| מעבדה | מופעים מרובים בחלונות מקוריים של Windows (ניסיוני), מספר יישומים ברקע |

> **מעבדה · מופעים מרובים (ניסיוני)**: כשזה מופעל, פתיחת יישום חדש לא סוגרת בכפייה את הקודם — כמה יישומים יכולים להישאר ברקע, לחזור אליהם בכל רגע ולשמור את מצב ההתחברות. מכיוון שלסביבת הרינדור של אנדרואיד יש רק חלון אמולטור אחד, בכל רגע נתון מוצג צג של יישום אחד בלבד; זה לא ריבוי חלונות אמיתי זה לצד זה. הפעלה מגדילה את צריכת הזיכרון. כבוי כברירת מחדל — התעלמו ממנו אם חשובה לכם יציבות.

> **DNS מהיר**: zApkStart מגיע כש-DNS המהיר **כבוי כברירת מחדל** (אנדרואיד האורחת משתמשת אז ב-DNS של המארח). אם פתירת השמות באנדרואיד איטית — למשל מאחורי VPN או רשת ארגונית — הפעילו אותו תחת הגדרות → רשת והורדות; הוא מכוון את אנדרואיד לשרתים ציבוריים מהירים. כבו אותו שוב אם פתירת שמות פנימיים משתבשת.

### 3.7 עדכונים מקוונים

הגדרות → עדכונים ואודות → בדיקת עדכונים, או קליק ימני במגש → בדיקת עדכונים. צינור העדכון בודק את המקורות ובוחר במהיר שבהם (GitHub ומראות מוגדרות), מוריד במקביל בחתיכות ומחליף מקור אוטומטית בכשל. עדכון לא נוגע בסביבת הריצה, ביישומים המותקנים או ב-snapshots.

גרסאות נייד חדשות תומכות ב**עדכון מצטבר**: בכל הפצה מתפרסם גם "מניפסט קוד" וחבילה קטנה שמכילה קוד בלבד (כמה MB, מול ‎~100 MB‎ לחבילה השלמה). אם גרסת מעטפת ה-Electron לא השתנתה, העדכון מוריד רק את החבילה הקטנה, מאמת קובץ-קובץ ומחליף את קוד התוכנה תוך שניות. אם גרסת המעטפת כן השתנתה, המניפסט חסר או שאימות כלשהו נכשל — התוכנה חוזרת אוטומטית לחבילה המלאה, כך שעדכון לא יכול לקלקל את התוכנה. גרסאות חנות מתעדכנות על ידי Microsoft Store.

> הערה: רק מי שמתקין גרסאות נייד דרך "בדיקת עדכונים" מ-GitHub מקבל עדכונים מצטברים; התקנות מ-Microsoft Store עוברות דרך החנות. לעדכון המצטבר אין שום השפעה על יישומים מותקנים, נתוני אנדרואיד, סביבת הריצה או snapshots.

## 4. שלושה מושגי ליבה (המפתח להבנת הודעות השגיאה)

רוב ה"בעיות המוזרות" מגיעות מאחד משלושת הדברים להלן. דקה של הבנה כאן תחסוך הרבה באבחון.

### 4.1 סביבת הרצה / תמונת המערכת

zApkStart לא מדמה "אנדרואיד ריק" — הוא טוען **תמונת מערכת Android 14 שלמה** כבסיס.
ב-0.6.3 יש **תמונה אוניברסלית אחת** (Google Play x86_64); גם יישומי x86 וגם ARM רצים עליה — אין עוד זוג "תמונת AOSP / תמונת תאימות" נפרד כמו בגרסאות ישנות.

- תמונה חסרה / פגומה, או לא תואמת לנתוני משתמש ישנים → כשל אתחול, אתחול תקוע, לופ הפעלות.
- נתוני המשתמש (‎`/data`‎) הם שכבת הפרש דקה; תמונת המערכת משותפת לכל המחשב.

### 4.2 האצת חומרה

כדי שהאמולטור ירוץ מהר הוא צריך האצת וירטואליזציה של המעבד. ב-Windows יש בדיוק שתי אפשרויות:

| שיטה | מה זה | מי צריך הרשאת מנהל | האם חובה אתחול אחרי התקנה? |
|---|---|---|---|
| **WHPX** | תכונה מובנית של Windows — "Windows Hypervisor Platform" | בהפעלת התכונה | כן |
| **AEHD** | מנהל התקן הליבה של Google | בהתקנת מנהל ההתקן | לא |

**זה רץ גם בלי האצה** (הדמיה תוכנתית טהורה, TCG) — פשוט האתחול לוקח דקות והתמונה נשמטת בקלות. זו "איטיות", לא "כשל". zApkStart חוזר אוטומטית למצב תקין ומנסה שוב עד 4 שילובי פרמטרים לאורך "מנוע רינדור → שיטת האצה → זיכרון/אתחול קר".

> אל תבלבלו בין **VirtualMachinePlatform** (של WSL2) לבין מתג ההאצה. לאמולטור דרוש **HypervisorPlatform**. עם הראשון בלבד, ‎`emulator -accel-check`‎ עדיין ידווח שההאצה לא זמינה.

### 4.3 שכבת התרגום של ARM

הרוב המוחלט של יישומי האנדרואיד מהשוק הסיני מספקים **ספריות מקוריות של ARM** (arm64-v8a / armeabi-v7a), ואילו תמונת המערכת היא **x86_64** — נדרשת "שכבת תרגום" שתעביר פקודות ARM למעבד x86. התמונה האוניברסלית של 0.6.3 כוללת בתוכה את שכבת ‎`ndk_translation`‎ החדשה, ולכן יישומי ARM בדרך כלל מותקנים בלי שום הגדרה.

- במפגש הראשון עם יישום ARM שרכיבי שכבת התרגום שלו עדיין לא במקום, zApkStart משלים אותם אוטומטית, מפעיל מחדש את סביבת הריצה ומנסה שוב (ראו 6.3).
- לתמונות ישנות (API 30) יש בעיות תאימות עם השכבה החדשה (למשל יישומי ByteDance שמפילים ‎`DoBadTrampoline`‎ SIGABRT); תמונת Android 14 תיקנה זאת.

## 5. לפני שמחפשים תקלה: בדיקת מצב וזיהוי אוטומטי

לפני שקוראים את המדריך, תנו לתוכנה לבדוק את עצמה — היא מתקנת אוטומטית את רוב הבעיות.

### 5.1 בדיקת מצב של המחשב · הגדרה אוטומטית

מיקום: הגדרות → אבחון ותיקון → **התחלת בדיקת מצב**

- מה נבדק: וירטואליזציה במעבד (VT-x/SVM) מופעלת, זמינות Hyper-V / Hypervisor Platform, כרטיס מסך / זיכרון וידאו / מנהל התקן, זיכרון, גרסת מערכת, ‎`emulator -accel-check`‎, מנהל ההתקן AEHD.
- לחיצה על "**החלת תצורה מומלצת**" כותבת אוטומטית את הפריטים הבטוחים: זיכרון / מספר ליבות / רזולוציית רינדור / איכות תמונה / הדמיה תוכנתית בכפייה כשאין האצה, ומקבעת אותם כפרופיל מנהל התקן למחשב הזה, שמוחל אוטומטית מעתה.
- התוצאות מדורגות: `ok` (תקין) / `warn` (עובד אבל כדאי לייעל) / `bad` (לא ירוץ עד לתיקון). לכל פריט יש צבע והסבר.

רק שני דברים באמת דורשים אתכם:

- **וירטואליזציה ב-BIOS**: אתחול לתוך ה-BIOS → הפעלת Intel VT-x / AMD SVM → Enabled (התוכנה לא יכולה לעשות זאת בשבילכם).
- **תכונות Windows / מנהל התקן ההאצה**: ראו 6.1.

### 5.2 זיהוי אוטומטי (דיבוג אוטומטי)

מיקום: הגדרות → אבחון ותיקון → "זיהוי אוטומטי · אבחון חכם"

כל 10 דקות ברקע התוכנה סורקת את המחשב, מציגה בעיות בשש קטגוריות ומציעה **תיקון בלחיצה אחת** לכל אחת (הפעלת סביבת הריצה מחדש, ניקוי נעילות, סגירת תהליכים יתומים, פסילת snapshots, ניקוי דיסק, איפוס רשת אנדרואיד…), ובודקת שוב אוטומטית אחרי התיקון:

| קטגוריה | בעיות שמכוסות |
|---|---|
| סביבת ריצה | הסיבה האמיתית לכשל האתחול הקודם, אתחול תקוע, קובצי נעילה שנותרו, תהליכי אמולטור יתומים, snapshot ריק, אין האצת חומרה |
| חיבור מכשיר | adb לא מאושר, offline, סביבת הריצה רצה אבל adb לא רואה מכשיר |
| אחסון | שטח פנוי בדיסק, תצורת מחיצת הנתונים מול המצב בפועל, תיקייה משותפת שאינה ניתנת לכתיבה |
| הגדרות | התנגשות כיוון מסך עם הפאנל הפיזי, מסך מלא אוטומטי שלא פועל בחלון נפרד |
| רשת/יומנים | אין רשת בצד אנדרואיד, מקורות הורדה לא נגישים, שגיאות ביומנים האחרונים |

> שני עקרונות: חיישן שנכשל לא מדווח כבעיה (אם לא ניתן לקרוא את המצב, נאמר "לא ידוע" — אף פעם לא ניחוש); אותה בעיה ישנה לא מפריעה שוב ושוב.

### 5.3 ייצוא דוח אבחון

מיקום: הגדרות → אבחון ותיקון → **ייצוא דוח אבחון** (או הכפתור באותו שם במסך שילוב המערכת)

הדוח הוא טקסט פשוט: תצורת המחשב, פרמטרי ההפעלה שנבחרו בפועל, יומנים ומסקנות אבחון. צרפו אותו כשמדווחים על בעיה — זה מקצר מאוד את האבחון.

### 5.4 המדריך המובנה והדרכות אוטומטיות

מגרסה 0.6.3 המדריך הזה **מוטמע בתוך התוכנה**: כפתור ה-"?" בשורת הכותרת של החלון הראשי ו"פתיחת מדריך המשתמש" תחת הגדרות → אודות פותחים אותו ישירות, עם חיפוש, גלילה והדפסה / שמירה כ-PDF. בעת הפתיחה הוא ממוקם אוטומטית בסעיף הרלוונטי לתקלה הנוכחית.

הזיהוי/התיקון האוטומטיים גם מביאים את ההדרכה אליכם:

- כשהזיהוי האוטומטי מוצא בעיה, ליד הפריט יש כפתור "הדרכה" שקופץ ישר לסעיף המתאים;
- עבור האצת חומרה, כשלי התקנה, שכבת תרגום ARM, אישור adb, אין-צליל וכדומה — **אחרי כשל של תיקון אוטומטי ההדרכה המתאימה נפתחת אוטומטית**, כך שלא צריך לחפש כאן;
- אותה הדרכה נפתחת אוטומטית לכל היותר פעם אחת בכל הרצה של התוכנה — היא לא תקטע אתכם שוב ושוב.

> כניסה ידנית: כפתור ה-`?` בשורת הכותרת. כדי להשהות זמנית את הפתיחה האוטומטית, כבו התראות בהגדרות הזיהוי האוטומטי; ההדרכות נגישות בכל זאת מכפתור "הדרכה" בפריט הבעיה.

## 6. פתרונות לבעיות נפוצות

### 6.1 ההודעה "האצת חומרה לא מופעלת" / אתחול איטי

**תסמינים**: ההגדרות/האבחון אומרים "אין כרגע האצת חומרה" / "האצת חומרה לא זמינה"; האתחול לוקח דקות והתמונה נשמטת.

**קודם כל, להבהיר**: בדרך כלל זו "איטיות", לא "לא נפתח". zApkStart כבר חזר אוטומטית להדמיה תוכנתית. את ההאצה צריך רק כדי להגיע לחלקות.

**לפי סוג הגרסה:**

- **התקנה / נייד**: הגדרות → אבחון ותיקון → בדיקת מצב של המחשב → למצוא "האצת חומרה לא מופעלת" → לחיצה על **תיקון**. מופיעה בקשת UAC אחת, ו-WHPX מופעל אוטומטית; אם זה נכשל (מערכת לא נתמכת או שלחצתם "לא"), מותקן במקום זאת מנהל ההתקן AEHD.
- **גרסת Microsoft Store (MSIX)**: יישומי חנות **לא יכולים להעלות הרשאות בעצמם**, ולכן לחיצה על "תיקון" פותחת את תיבת הדו-שיח "הפעלה או כיבוי של תכונות Windows":
  1. לסמן את **"Windows Hypervisor Platform" (HypervisorPlatform)**;
  2. לאשר ולבצע **הפעלה מחדש של המחשב** פעם אחת.

  אפשר גם להריץ ב-**PowerShell כמנהל**:

  ```powershell
  dism /online /enable-feature /featurename:HypervisorPlatform /all /norestart
  dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
  ```

> שתי מלכודות: ① אל תפעילו רק את VirtualMachinePlatform — זה לא ההאצה שהאמולטור צריך; ② אם VT-x/SVM כבויים ב-BIOS, הפעילו אותם קודם לפי 5.1, אחרת הפעלת תכונת ה-Windows לא תועיל.
> אם מנהל התקן כרטיס המסך ישן מ-3 שנים, עדכנו אותו מאתר היצרן; אבל zApkStart לא מתקין מנהלי התקנים בעצמו (התקנה שגויה מחמירה את המצב). חלק מכרטיסי המסך הישנים / המובנים זקוקים לטלאי תאימות: ראו הגדרות → אבחון ותיקון → מנהל התקן · טלאי תאימות.

### 6.2 כשלי התקנה (INSTALL_FAILED_*)

**תסמינים**: התקנת יישום נכשלת; ההודעה בדרך כלל מתחילה ב-"Install failed:" ומסתיימת בקוד שגיאה ‎`INSTALL_*`‎.

zApkStart מתרגם את שגיאות האנגלית המקוריות. השוו מול הטבלה:

| קוד | משמעות | מה עושים |
|---|---|---|
| `INSTALL_FAILED_NO_MATCHING_ABIS` | היישום מספק ספריות ARM בלבד ולתמונה הנוכחית אין שכבת תרגום ARM | **בדרך כלל מטופל אוטומטית**: zApkStart מחליף תמונה ומנסה שוב. ראו [6.3](#troubleshoot-arm) |
| `INSTALL_FAILED_OLDER_SDK` | היישום דורש אנדרואיד חדש יותר | נדרשת תמונת מערכת חדשה יותר; כרגע Android 14 (API 34), נדיר |
| `INSTALL_PARSE_FAILED_NO_CERTIFICATES` | ל-APK אין חתימה תקפה | ה-APK פגום או לא רשמי; השיגו את החבילה מחדש |
| `INSTALL_PARSE_FAILED_INCONSISTENT_CERTIFICATES` / `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | החתימה שונה מהגרסה המותקנת | קודם להסיר את הגרסה הישנה ואז להתקין |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | כבר מותקנת גרסה חדשה יותר | אי אפשר להחליף בירידת גרסה; התקינו גרסה גבוהה יותר או הסירו קודם |
| `INSTALL_FAILED_INSUFFICIENT_STORAGE` | אין מקום בדיסק של סביבת הריצה | נקו את הדיסק, או העבירו את תיקיית נתוני סביבת הריצה לכונן פנוי (הגדרות → שילוב מערכת) |
| `INSTALL_FAILED_INVALID_APK` | APK פגום/חלקי | ייתכן הורדה שלא הושלמה; הורידו מחדש |
| `INSTALL_FAILED_INVALID_URI` | נתיב ה-APK מכיל תווים מיוחדים/לא אנגליים | העבירו את ה-APK לנתיב ASCII פשוט והתקינו שוב |
| `INSTALL_FAILED_ALREADY_EXISTS` | קיים כבר באותו שם עם חתימה שונה | הסירו קודם |
| `INSTALL_FAILED_DEPRECATED_SDK_VERSION` | יישום המכוון לאנדרואיד עתיק מאוד | **מטופל אוטומטית**: zApkStart מנסה שוב עם פרמטר העקיפה הרשמי |
| `INSTALL_FAILED_TEST_ONLY` | חבילת בדיקות בלבד | **מטופל אוטומטית**: מנסה שוב עם פרמטר חבילת הבדיקות |
| `INSTALL_FAILED_MISSING_SHARED_LIBRARY` | תכונת מכשיר/ספריית יצרן נדרשת חסרה | היישום תלוי בסביבת יצרן ספציפית שאמולטור לא יכול לספק |
| `INSTALL_FAILED_USER_RESTRICTION` | המערכת חוסמת התקנה | הפעילו מחדש את סביבת הריצה ונסו שוב |
| `INSTALL_FAILED_CONFLICTING_PROVIDER` | ContentProvider מתנגש עם יישום מותקן | הסירו את היישום המתנגש |
| `INSTALL_FAILED_INTERNAL_ERROR` | שגיאת מערכת פנימית (בדרך כלל מקום לא מספיק או אתחול שלא הושלם) | הפעילו מחדש את סביבת הריצה, המתינו לסיום האתחול ונסו שוב |

> אם תקבלו אנגלית גולמית מחוץ לטבלה, ייצאו דוח אבחון לפי 5.3 ודווחו.

### 6.3 אין שכבת תרגום ARM בתמונת המערכת / יישומי ARM נכשלים בהתקנה או קורסים

**תסמינים**: בהתקנה מופיע ‎`INSTALL_FAILED_NO_MATCHING_ABIS`‎ עם נוסח כמו "היישום מספק ספריות מקוריות של ARM בלבד… לתמונת המערכת הנוכחית אין שכבת תרגום ARM"; או שהיישום מותקן אבל קורס מיד בהפעלה, עם ‎`DoBadTrampoline`‎, ‎`libndk_translation`‎, ‎`UnsatisfiedLinkError`‎, ‎`...so not found`‎ ביומנים.

**רקע**: 0.6.3 משתמש ב**תמונת Android 14 אוניברסלית אחת** שתומכת גם ב-x86 וגם ב-ARM, עם שכבת התרגום מובנית. גרסאות ישנות דרשו החלפת תמונה ידנית; המתג "תמונת תאימות אוניברסלית (מנוהלת אוטומטית)" היום **מיועד רק לתאימות לתצורות ישנות — בדרך כלל אין לגעת בו**.

**מה zApkStart עושה אוטומטית:**

1. אם ההתקנה מדווחת ‎`NO_MATCHING_ABIS`‎ — מעבר אוטומטי לתמונת התאימות → הפעלת סביבת הריצה מחדש → התקנה מחדש של היישומים המותקנים מגיבויי ה-APK המקומיים → ניסיון התקנה חוזר (ביומן: "מחליף לתמונת התאימות ומפעיל מחדש את סביבת הריצה…").
2. אם יישום קורס בהפעלה והיומנים מצביעים בבירור על שכבת תרגום ARM (למשל ‎`DoBadTrampoline`‎) — מעבר אוטומטי לתמונת התאימות של Android 14 וניסיון חוזר (ביומן: "זוהתה קריסת שכבת תרגום ARM, מחליף לתמונת תאימות אוטומטית…").

**מה נדרש מכם:**

- **להיות סבלניים**: החלפת תמונה מפעילה מחדש את סביבת הריצה — כ-40 שניות עד דקה — וייתכן שיופיע חלון התקדמות.
- **לוודא שהתמונה במקום**: הגדרות → כללי והתקנה → סביבת ריצה, לבדוק את מצב "תמונת תאימות אוניברסלית (מנוהלת אוטומטית)"; אם מוצג שלא הורדה, לחצו על "הורדת תמונת תאימות" (‎~1.5 GB‎), ואחרי השלמתה **הפעילו מחדש את סביבת הריצה** כדי שייכנס לתוקף.
- **עדיין קורס**: מיעוט של יישומים מכיל בדיקות אנטי-הדמיה עמוקות יותר (אימות כפוי של חיישנים אמיתיים, מודם וכדומה) ופשוט לא יכול לרוץ באמולטור; ליישומים כאלה יש הסבר בשפה פשוטה — זו מגבלה, לא תקלה.

**מה עושים כשמופיע ""התקנה נכשלה" באדום אבל הנוסח אומר "מנסה שוב אחרי מעבר לתמונת תאימות"?**

זו הייתה שגיאת תצוגה בגרסאות ישנות: קובץ התמונה היה על הדיסק, אבל נעשה בו שימוש חוזר בסביבת ריצה ישנה ששכבת התרגום שלה כבויה, המעבר והניסיון החוזר דולגו ודווח כשל בעוד הנוסח המשיך לטעון "מנסה שוב". **אינכם על הקוד החדש ביותר — שדרגו ל-build החדש ביותר של 0.6.4** (תוקן בגרסה שאליה מתועד המדריך הזה: לפני ההתקנה נבדקת יכולת התרגום האמיתית של סביבת הריצה במקום רק לבדוק שהקובץ קיים; ‎`NO_MATCHING_ABIS`‎ תמיד מפעיל מעבר + הפעלה מחדש + פסילת snapshot ישן לפני התקנה מחדש; כשל שני מדווח כהוויתו, בלי לטעון "מנסה שוב"). שדרגו והתקינו את היישום שוב.

> נבדק בשטח: אפליקציית Hongguo (com.phoenix.read, arm64-v8a בלבד) מותקנת, נכנסת לפיד ההמלצות ומנגנת וידאו כרגיל על תמונת Android 14 + שכבת התרגום החדשה. ‎`ro.product.cpu.abilist`‎ של סביבת הריצה = ‎`x86_64,arm64-v8a`‎ — השכבה פעילה.

### 6.4 adb לא מאושר (אישור ניפוי USB)

**תסמינים**: האבחון מדווח "adb לא מאושר" או "אישור הניפוי של אנדרואיד לא הושלם"; ‎`adb devices`‎ מציג `unauthorized`; היישומים לא מתחילים.

**הסדר הנכון:**

1. בדקו אם יש חלון אמולטור עם תיבת הדו-שיח **"אישור ניפוי USB?"** — לחצו שם על **אישור**, וסמנו **"אפשר תמיד ניפוי מהמחשב הזה"** כדי שלא ישאל שוב.
2. אם החלון לא ניתן ללחיצה או לא מופיע: הגדרות → סביבת ריצה → **איפוס נתוני אנדרואיד / מחיקת נתוני אנדרואיד**, ואז נסו שוב (היישומים המותקנים נמחקים; קובצי ה-APK נשארים ומותקנים אוטומטית מחדש; המערכת עצמה לא נפגעת).

> ⚠️ **אל תמחקו את ‎`%USERPROFILE%\.android\adbkey`‎**. נבדק בשטח: זו בדיוק הפעולה ההפוכה. אנדרואיד כותב מפתח ציבורי חדש רק כשקובץ ‎`adb_keys`‎ לא קיים; אם תחליפו מפתח פרטי חדש והמערכת עדיין מחזיקה את המפתח הציבורי הישן — השניים לא יתאימו לעולם והאישור ייכשל תמיד.

> בדיקה משורת הפקודה: שירות ה-adb של zApkStart רץ על **הפורט הייעודי 5044** (מופרד לחלוטין מ-5037 שלכם):
> ```powershell
> $env:ANDROID_ADB_SERVER_PORT = 5044
> adb devices    # אמור להציג emulator-5554
> ```
> אל תריצו ‎`adb connect`‎ ידני לפורט 5555 — תמונת ה-Play קופצת "אישור ניפוי USB" מעל היישום, מה שנראה כאילו התוכנה שבורה.

### 6.5 לחיצה כפולה על הסמל לא עושה דבר / המתנה אינסופית / חלון עם כפתור מסתובב

הבעיות האלה כמעט תמיד מצביעות על **נקודת הכניסה או השתלטות החלון**. בדקו לפי הסדר.

**① ודאו שאתם מריצים את הגרסה החדשה**

- בדקו את תחילת ‎`%APPDATA%\zApkStart\logs\app.log`‎: היא צריכה לומר `start v0.6.4`. אם מופיע `v0.5.x` — קיצור הדרך בשולחן העבודה/תפריט התחל מצביע על התיקייה הישנה.
- גרסאות ישנות (0.5.x) לא כללו סביבת ריצה וברירת המחדל שלהן הייתה חלון מוטמע → "איטי מאוד + חלון מעטפת עם כפתור מסתובב". עברו ל-0.6.4 וכוונו את קיצור הדרך אל ‎`zApkStart.exe`‎ החדש.

**② צפו אורך אתחול הוגן**

אתחול קר כ-23–48 שניות, הפעלה מחדש עקב שינוי כיוון כ-50 שניות — שניהם בטווח התקין. בזמן הזה לחיצה על הסמל נראית כמו "שום דבר לא קורה" בעוד המכונה מאתחלת ברקע. **אל תלחצו שוב ושוב**: לחיצות מרובות גורמות למופע שני להשתלט על האמולטור, והסיום של המופע הראשון עם היציאה עלול לכבות את האמולטור ולהפיל את ההפעלה (ב-0.6.3 נוספה הגנת ‎`owner.pid`‎, אבל ההמתנה בתור עדיין נראית כמו "שום דבר לא קורה"). לחצו פעם אחת וחכו.

**③ החלון המקורי לא השתלט → חזרה לחלון מוטמע עם כפתור הסיבוב**

אם ביומן מופיעים `attach failed`, `emu:0` — סוכן החלונות לא מצא את חלון האמולטור והתוכנה חזרה למצב מוטמע (חלון המעטפת עם שורת כותרת וכפתור סיבוב שאתם רואים).
- הפעלה דרך קישור תיקייה (junction) / נתיב לא סטנדרטי נוטה להפעיל זאת; ב-0.6.3 הסוכן מפענח את הנתיב האמיתי לפני ההתאמה. אם זה עדיין קורה, צרפו את היומן בדיווח.

**④ איפוס נתוני אנדרואיד (צעד אחרון)**

הגדרות → כללי והתקנה → **איפוס נתוני אנדרואיד** (אישור כפול). מוחק יישומים מותקנים ואת הנתונים שלהם אבל שומר על המערכת עצמה; רשימת היישומים נשמרת והם מותקנים אוטומטית בפתיחה. מתאים למחיצת נתונים פגומה או לכל "לא נפתח" שנגרם מ-‎`/data`‎ שנכשל בעגינה.

### 6.6 טבלת עזרה לשאר בעיות ההפעלה

zApkStart **כבר מטפל אוטומטית** ברוב שגיאות הריצה האלה; הטבלה מסבירה מה הוא עושה ומה נשאר לכם. אם הטיפול האוטומטי לא עוזר, ייצאו דוח אבחון לפי 5.3.

| כותרת האבחון | טיפול אוטומטי | מה עוד אפשר לעשות |
|---|---|---|
| האצת חומרה לא זמינה | חזרה להדמיה תוכנתית | להפעיל האצה לפי 6.1 |
| הקצאת זיכרון נכשלה | הורדת זיכרון ומספר ליבות | לסגור תוכנות גוזלות זיכרון |
| פורט האמולטור תפוס | בחירה אוטומטית בפורט פנוי | לצאת מאמולטורים אחרים (Nox/MuMu/BlueStacks) או לאתחל |
| קובצי נעילה שנותרו / "Running multiple emulators with the same AVD" | ניקוי נעילות AVD וניסיון חוזר | לוודא שאין אמולטור אחר על אותה סביבת ריצה |
| תמונת מערכת חסרה/פגומה/לא תואמת לנתונים ישנים | אתחול מחדש עם נתוני משתמש נקיים | הגדרות → סביבת ריצה: למחוק את התמונה ולהוריד מחדש |
| snapshot של אתחול מהיר פגום | השלכת ה-snapshot הישן ואתחול קר | היציאה התקנה הבאה בונה אותו מחדש; או לכבות snapshots |
| רכיבי סביבת ריצה נמחקו / חסר ספריית VC++ | — | להוסיף את zApkStart לרשימת החריגים של האנטי-וירוס ולחלץ מחדש; להתקין את Microsoft VC++ 2015-2022 |
| אין מספיק שטח בדיסק | — | להעביר את תיקיית סביבת הריצה לכונן פנוי; לכבות snapshots / להקטין את מחיצת הנתונים |
| נתיב מכיל תווים לא אנגליים/מיוחדים | מעבר אוטומטי לנתיבים קצרים | להעביר את zApkStart לתיקיית ASCII פשוטה (למשל ‎`C:\zApkStart`‎) |

| סביבת הריצה הנוכחית דוחה את מצב ה-GPU | בחירה מחדש במצב GPU אפשרי לפי גרסת המנוע | — |

**סמלי שולחן העבודה מציגים את הסמל של zApkStart / סמלים ריקים**: הגדרות → שילוב מערכת → **בניית קיצורי דרך מחדש** (כותב מחדש את קיצורי הדרך בשולחן העבודה ובתפריט התחל לפי רשימת היישומים הנוכחית, ומתקן יחד גם את הסמלים ואת זהות שורת המשימות). בנייה מחדש נדרשת גם אם קיצור דרך הוזז ממקומו והנתיב שלו התיישן.

### 6.7 אין צליל ביישומים / הצליל חלש מדי

**תסמינים**: וידאו וצלילי התראה ביישומי אנדרואיד שקטים לחלוטין; או שלשאר Windows יש צליל אבל רק ליישומים של zApkStart אין.

**קודם להפריד**: אם למערכת עצמה אין צליל — תקנו קודם את השמע של Windows; המשיכו להלן רק כשלשאר המערכת יש צליל ורק ליישומים של zApkStart אין.

1. **עוצמה והתקן פלט ב-Windows**: לחצו על סמל השמע בשורת המשימות; ודאו ששום דבר לא מושתק, העוצמה לא 0, והתקן הפלט הוא האוזניות/הרמקולים שבהם אתם באמת משתמשים. פתחו את "מיקסר עוצמת הקול" ובדקו אם השורה של zApkStart / סביבת הריצה של אנדרואיד מושתקת בנפרד או עומדת על 0.
2. **עוצמה בתוך היישום**: חלק מהיישומים מאפסים את עוצמת המדיה בכניסה ראשונה — הגבירו בהגדרות היישום או במקשי העוצמה של אנדרואיד. יישומי וידאו מסוימים גם משביתים השמעה אוטומטית בתוך היישום.
3. **מתג הצליל של zApkStart**: הגדרות → ביצועים ומשאבים → **שמע אנדרואיד** חייב להיות מסומן. הזיהוי האוטומטי עוקב אחריו; אם הוא מוצא אותו כבוי, הוא מדווח תחת "הגדרות → אבחון ותיקון" ולחיצה אחת מפעילה אותו בחזרה. **אחרי שינוי חובה להפעיל מחדש את סביבת הריצה של אנדרואיד** (האמולטור מופעל עם ‎`-no-audio`‎ רק כשגם הצליל וגם המיקרופון כבויים; שינוי בזמן ריצה לא מחזיר צליל מיד).
4. **שירות השמע של Windows**: ‎`Win+R`‎ והריצו `services.msc`, מצאו את **Windows Audio**, ודאו שהמצב "פועל" וסוג ההפעלה "אוטומטי". אם מנוטרל — קליק ימני → הפעלה; הזיהוי האוטומטי (מ-0.6.3) גם מזהה ומדווח זאת. ב-PowerShell כמנהל אפשר ‎`net start Audiosrv`‎.
5. **אוזניות Bluetooth / מספר התקני פלט**: אחרי מעבר לאוזניות Bluetooth לפעמים Windows לא מעביר תוכניות פעילות. נתקו וחברו מחדש את האוזניות, או הפעילו מחדש את סביבת הריצה.
6. **עדיין שקט**: ייצוא דוח אבחון תחת "הגדרות → אבחון ותיקון" ודיווח; הדוח כולל את מצב מתג הצליל ושירות השמע, וזה ממקם אם מדובר בתצורה, בשירות מערכת או ביישום עצמו.

> כשהתיקון האוטומטי נכשל, התוכנה פותחת את הסעיף הזה בעצמה. אם כיביתם את התראות הזיהוי האוטומטי, אפשר להגיע לכאן גם דרך כפתור "הדרכה" בפריט הבעיה או ה-`?` בשורת הכותרת.

### 6.8 כשל הפעלה בגרסת החנות / 0xC0000135 (טעינת DLL נכשלה)

**תסמינים**: פתיחת יישום מסתובבת לנצח או יוצאת מיד; דוח האבחון מציג קוד יציאה ‎`0xC0000135`‎ (עשרוני: `3221225781`). נפוץ בעיקר בגרסאות **המותקנות מחבילת Microsoft Store (MSIX)**.

**קודם כל, תיקון של טעות נפוצה**: ‎`0xC0000135`‎ אומר רק "קובץ DLL כלשהו לא נטען". זה **לא** אומר אוטומטית שחסרה ספריית VC++, וזה **לא** אומר אוטומטית שהאנטי-וירוס מחק קבצים. שלוש אפשרויות חולקות את קוד היציאה הזה — אל תריצו שוב ושוב להתקין את VC++:

1. **מגבלת הנתיב של גרסת החנות (MSIX)**: גרסאות חנות יושבות בתיקיית ‎`C:\Program Files\WindowsApps\...`‎ שהיא לקריאה בלבד. כשסביבת הריצה של אנדרואיד מריצה משם ‎`qemu`‎ וחבריה, התהליכים הבנים מאתרים DLL בנתיב יחסי, והפניית הנתיבים / בידוד הסביבה של הקונטיינר עלול לשבור זאת, ואז הם יוצאים עם ‎`0xC0000135`‎. זה ייחודי לגרסת החנות ואין כמות של התקנות VC++ חוזרות שתתקן זאת.
2. **חסרה באמת ספריית VC++**: סביבת הריצה של אנדרואיד (Qt6 / qemu) תלויה ב-Microsoft VC++ 2015-2022 (x64). אם בהגדרות → אבחון ותיקון מדווח במפורש "חסרה ספריית VC++ (x64)" — זה **נבדק על ידי בדיקה שקבצי ה-dll באמת קיימים**, והתיקון שלו בלחיצה אחת מתקין אותה.
3. **האנטי-וירוס הסגיר קבצי סביבת ריצה**: dll בתיקיית סביבת הריצה שהוסגר/נמחק מייצר גם את הקוד הזה. הוסיפו את תיקיית ההתקנה של zApkStart ואת תיקיית נתוני סביבת הריצה לרשימת החריגים של האנטי-וירוס, ואז התקינו פעם אחת מחדש.

**אבחון לפי הסדר:**

1. **לבדוק אם האבחון באמת מדווח VC++**: אם במסך ההגדרות מופיע "חסרה ספריית VC++ (x64)", לחצו על התיקון שלו. אחרי ההתקנה הפעילו את המחשב מחדש ונסו שוב. אל תתקינו רק כי קוד היציאה הוא ‎`0xC0000135`‎ — קודם ודאו שהפריט הזה אכן מדווח.
2. **לא דווח VC++, ועדיין נכשל → כנראה בעיית הנתיב של גרסת החנות**: זו הסיבה הסבירה ביותר כיום. נסו לפי הסדר:
   - לצאת מ-zApkStart לחלוטין (סמל המגש → יציאה) ולפתוח מחדש;
   - לבדוק באנטי-וירוס את "גישה מבוקרת לתיקיות / הגנה מתוכנות כופר", להוסיף את zApkStart לחריגים ולהפעיל מחדש;
   - אם עדיין נכשל — להשתמש ב**גרסה הניידת** (`zApkStart-win64-portable` מההפצות של ה-fork ב-GitHub) בתיקיית ASCII פשוטה (למשל ‎`C:\zApkStart`‎) — הגרסה הניידת לא יושבת תחת WindowsApps ועוקפת לגמרי את המגבלה.
3. **רוצים את שם ה-DLL שנכשל בדיוק** (מתקדם): בדיווח, הנתון השווה ביותר הוא איזה dll חסר בפועל. ב-Event Viewer → Windows logs → Application מצאו את רשומת ‎`Application Error`‎ של zApkStart / emulator וקראו את השדה ‎`FaultingModuleName`‎; או ייצוא דוח אבחון תחת "הגדרות → אבחון ותיקון" וצירופו.
4. **מה אם adb גם קורס**: אם ביומן האירועים מופיע בנפרד ‎`adb.exe`‎ עם ‎`0xC0000409`‎ — זו בעיה עצמאית (חריגה בחיבור מכשיר), לא הגורם הישיר ליציאת האמולטור; טפלו בהפעלה לפי 1–3 לעיל וציינו את בעיית ה-adb בנפרד בדיווח.

> הסעיף הזה נפתח אוטומטית: כשכשל הפעלה / כשל תיקון מסווג כבעיית DLL, התוכנה קופצת לכאן ישירות. אפשר להגיע לכאן גם ידנית דרך כפתור "הדרכה" בפריט הבעיה או ה-`?` בשורת הכותרת.

### 6.9 יישומים לא מצליחים להשתמש במיקרופון / שיחות קוליות והקלטה נכשלות

**תסמינים**: הודעות קוליות, שיחות, הקלטה, "סריקה לדיבור" וכדומה נכשלים ביישומים, עם הודעות כמו "אין מיקרופון / התקן הקלטה לא זמין".

1. **מתג המיקרופון של zApkStart**: הגדרות → ביצועים ומשאבים → **קלט מיקרופון** חייב להיות מסומן. מופעל כברירת מחדל; אם כובה, הזיהוי האוטומטי מדווח "קלט המיקרופון כבוי בהגדרות" תחת "הגדרות → אבחון ותיקון", ולחיצה אחת מפעילה אותו מחדש ומפעילה מחדש את סביבת הריצה. **אחרי שינוי חובה להפעיל מחדש את סביבת הריצה של אנדרואיד** (המתג קובע אם האמולטור חושף התקן הקלטה לאנדרואיד).
2. **הרשאת מיקרופון ב-Windows**: ‎`הגדרות → פרטיות ואבטחה → מיקרופון`‎ — ודאו שגם "אפשר ליישומים גישה למיקרופון" וגם "אפשר ליישומי שולחן עבודה גישה למיקרופון" דלוקים. אנדרואיד רץ בתוך יישום שולחן עבודה; בלי זה המערכת לא תמסור מיקרופון בכלל.
3. **לוודא ש-Windows מקליט**: הקליטו קטע עם "מקליט הקול" המובנה כדי לוודא שהמיקרופון עצמו והתקן הקלט (מיקרופון אוזניות / מיקרופון מצלמה / מיקרופון נפרד) עובדים ולא מושתקים.
4. **התקן הקלט הנכון**: כשמחוברים כמה מיקרופונים, הגדירו את זה שרוצים כהתקן ברירת מחדל תחת "הגדרות צליל → קלט" ב-Windows; האמולטור משתמש בהתקן הקלט ברירת המחדל של המערכת.
5. **היחס בין צליל למיקרופון**: רק כש**גם** "שמע אנדרואיד" **וגם** "קלט מיקרופון" כבויים מכבה האמולטור את כל תת-מערכת השמע לחיסכון במעבד; כל עוד אחד דלוק, השני עובד כרגיל.

> כשהמיקרופון כבוי, בצד היישום פשוט "לא נמצא התקן הקלטה" — בלי שגיאה רועשת. הזיהוי האוטומטי מדווח על זה ביוזמתו; אפשר להגיע לסעיף הזה גם ידנית דרך ה-`?` בשורת הכותרת.

### 6.10 רינדור בכרטיס מסך ייעודי / מובנה (העדפת מאיץ גרפי)

**תסמינים**: למחשב יש כרטיס מסך ייעודי אבל התמונה ביישומים מתנגדת ונשמטת; או שמחשב נייד מתחמם ומרוקן סוללה ומעדיפים את המובנה לחיסכון.

zApkStart מרנדר את הגרפיקה של אנדרואיד עם ‎`-gpu host`‎ — רינדור חומרתי אמיתי דרך כרטיס המסך בפועל. מ-0.6.4 כל יצרן GPU (NVIDIA / AMD / Intel) ברירת המחדל היא host, במקום ההתנהגות הישנה שהכריחה AMD/Intel לרינדור תוכנתי — כלומר לוותר על הכרטיס מרצון. אם host קורס על מכונה נתונה, יש ירידה אוטומטית למנוע תוכנתי; השימוש לא נפגע.

**בחירת הכרטיס**: במחשבים עם גם ייעודי וגם מובנה, לפעמים Windows מקצה את האמולטור למובנה. הגדרות → ביצועים ומשאבים → **העדפת מאיץ גרפי** קובעת זאת במפורש:

| אפשרות | מתאים ל |
|---|---|
| ברירת מחדל של המערכת (מומלץ) | לתת ל-Windows לבחור לפי צריכת חשמל/עומס; הכי פשוט ברוב המחשבים |
| העדפת כרטיס ייעודי | משחקים, וידאו, כל מה שצריך קצב פריימים גבוה; יותר חום וצריכת סוללה |
| העדפת כרטיס מובנה | יישומים קלים, שהייה ברקע, חיסכון בסוללה בנייד; ביצועים נמוכים יותר |

- זה עובד דרך "העדפת ביצועים גרפיים" של Windows (UserGpuPreferences) על תהליך האמולטור, **תקף רק ב-Windows 10 1803 ומעלה**; מערכות ישנות מתעלמות אוטומטית בלי להשפיע על ההפעלה.
- נכנס לתוקף ב**הפעלה הבאה של סביבת הריצה של אנדרואיד**; מסך ההגדרות מציג אם היא כרגע בתוקף.
- במנהלי התקן AMD ישנים host לפעמים קורס: עדכנו את מנהל ההתקן הגרפי; אם זה לא עוזר, הפעילו את טלאי ה-swangle לדוגמה של הכרטיס המובנה AMD הכלול בחבילה תחת "הגדרות → אבחון ותיקון → מנהל התקן · טלאי תאימות" כדי לקבע את הרינדור למנוע יציב יותר.

## 8. נתונים ותיקיות

| שימוש | מיקום |
|---|---|
| סביבת ריצה (adb / emulator / תמונות) | מובנית בחבילה, או ‎`%APPDATA%\zapkstart\runtime`‎ (נייד קל) |
| תמונת המערכת לאחר חילוץ | ‎`%APPDATA%\zapkstart\system-images`‎ |
| AVD / יישומים מותקנים / snapshots | ‎`%APPDATA%\zapkstart\avd`‎ |
| סמלי יישומים | ‎`%APPDATA%\zapkstart\icons\<חבילה>.ico`‎ |
| הגדרות ורשימת יישומים | ‎`%APPDATA%\zApkStart\settings.json`‎ / ‎`apps.json`‎ |
| יומני ריצה / דוחות אבחון | ‎`%APPDATA%\zApkStart\logs\`‎ |
| תיקייה משותפת Windows ↔ אנדרואיד | ‎`%USERPROFILE%\zApkStartShared`‎ ↔ ‎`/sdcard/zApkStartShared`‎ |

> "איפוס נתוני אנדרואיד" מנקה רק את שכבת נתוני המשתמש; תמונת המערכת וקובצי ה-APK נשמרים. עדכון יישומים לא מאבד את סביבת הריצה, יישומים מותקנים או snapshots.
>
> מומלץ להשאיר מקום פנוי נדיב בכונן C:‏: חילוץ התמונה + מחיצת הנתונים + snapshots יחד יכולים להגיע לכמה GB. מחסור בשטח גורם לכשלי התקנה/אתחול.

## Windows ARM64

zApkStart מגיע ב-build ARM64 מקורי של היישום עצמו. מה שמנוע האנדרואיד יכול ולא יכול לעשות הוא עובדה חומרתית, והיישום מספר על זה ביושר:

| מארח | המעטפת (היישום) | מנוע האנדרואיד |
|---|---|---|
| Windows 10/11 x64 | מקורי | מקורי (Google emulator / QEMU x64, האצה ב-AEHD או WHPX) — חוויה מלאה |
| Windows 11 ARM64 | מקורי (build ARM64) | **לא זמין באופן מקורי.** Google לא מפרסמת בינאריים של אמולטור ל-ARM64; מנוע ה-x64 תחת האמולציה של Windows מתורגם פעמיים בתוכנה ואינו שמיש ליישומים אמיתיים |

- ב-ARM64, היישום מדווח על המצב בהפעלה הראשונה.
- הרצת מנוע ה-x64 תחת האמולציה של Windows היא **בחירה מפורשת** (ניסיון אחד, עם ציפיות מוצהרות מראש) — לעולם לא ברירת מחדל.
- מנוע אנדרואיד מקורי אמיתי ל-ARM64 מתועד — לא משוחרר — ב-‎`docs/zapkstart/arm64-research.md`‎ במאגר.
- במכשירי ARM64 יש להשתמש ב-build הנייד הקל של ARM64; כל שאר המדריך (הגדרות, אבחון, עדכונים) חל באותה צורה.

Install Android to the virtual disk

The virtual machine window is open. Follow the 6 steps below once; afterwards zApkStart boots straight from the disk and no longer needs an image.

  1. Boot menu: use ↓ to pick Installation - Install Android-x86 to harddisk, press Enter
  2. Choose Partition: pick Create/Modify partitions; when asked about GPT choose No
  3. cfdisk partitioning: New → Primary → press Enter for the size → Bootable → Write → type yes → Quit
  4. Format: pick vda1 → choose ext4 when asked to format → Yes
  5. Bootloader & system: choose Yes for Install GRUB; choose Yes for Install /system as read-write
  6. Finish: once progress hits 100%, click "I finished installing" below (zApkStart restarts and takes over automatically)

If adb is later reported not connected: press Ctrl+Alt+F1 in the VM window to open a terminal, run setprop service.adb.tcp.port 5555, stop adbd, start adbd, then press Ctrl+Alt+F7 to return to the GUI.

App window
Press F11 anytime or use the tray menu; fullscreen only enlarges the window without changing the picture ratio and does not restart the app.
When on, opening an app fills the screen directly, no F11 needed. Best combined with "Landscape" below — the landscape panel's aspect ratio already fits the screen, so fullscreen has no black bars.
Android's orientation is decided by the real orientation of the virtual phone panel. When the panel orientation differs from what the app declares, Android only gives the app a narrow center strip with black on both sides — resizing the window or changing the resolution never fills it. "Follow the app" reads the app's orientation when the APK is installed and switches the panel automatically at launch, so these apps stand upright and fill the screen. The runtime only restarts once (a dozen or so seconds) when the orientation must change; after that, same-orientation apps open instantly.
Android's auto-rotate switch defaults to on. Note this does not affect the picture orientation: panel and screen orientation are still decided by the policy above plus ignoring app orientation requests, not by the sensor. Only the rare app that reads this switch's value uses it.
720 wide at 190dpi equals 606dp, just past Android's 600dp tablet breakpoint; two-column episode pages and split settings panes only appear in this layout. Turning it off returns to the phone layout (bigger text, less info). The change applies the next time an app opens.
This is the physical panel orientation the runtime uses right now, written automatically by the policy above. Only in "forced" mode is it entirely yours to decide.
The native window is rendered and laid out by the emulator directly; dragging, scaling and rotation track the pointer without black bars or misaligned clicks, at the cost of one extra taskbar icon (rotate landscape from the tray menu or Ctrl+Alt+R). Embed mode stuffs the emulator window into ours — looks more uniform with built-in rotate buttons, but drops frames and shows black bars when scaling/rotating/switching apps. Changes apply the next time an app opens.
In window mode the border can be dragged to any size; this tunes Android's internal render size — smaller saves performance.

Container details (advanced)
Tightens vCPU quotas and lowers process priority so CPU goes to the Windows desktop first. The "Resource profile" above already sets this automatically.
Game mode keeps the Android VM at higher CPU priority and reduces host-side polling for the lowest input and video latency; other programs on the machine slow down. Without an app window the container still parks itself at lower priority.
Additionally disables background packages like the Play Store, setup wizard and print services, keeping only what apps need to run. If an app complains about missing Google Play services, turning this off restores them automatically.
Boots the Android environment in the background right after zApkStart starts (the window stays hidden; you never see the emulator). Afterwards any app is one "Open" away — measured from 20+ seconds down to almost none. The cost is ~1GB resident memory while idle; turned off, the first app launch needs a cold boot.
The Android environment boots once and stays resident; afterwards opening an app does not rerun the whole system — it starts that app and stops other apps' processes. Closing the last window clears the background and parks the container; the next launch is still instant.
Downloads & update source
zApkStart gets updates and runtime components only from its own GitHub Releases; if downloads are slow, enable the public mirror acceleration or fill in a custom prefix.
When GitHub direct connection is slow, also speed-tests the two public forwarding services ghfast.top / gh-proxy.com (they only forward public release files, no accounts involved). Turn off to use only direct connection and your own prefix.
If set, only your prefix is used and the two public mirrors above are skipped; leave empty for the "auto" logic. The downloader prepends it to the real URL.
Large files download in parallel chunks. The default 8 connections saturate most home broadband; try 16 when the network is stable.
Machine check · auto config
First scans this machine: is CPU virtualization on, is the Windows Hypervisor Platform present, what GPU and how much VRAM, is memory and OS version enough. What can be set automatically (memory / cores / quality / render backend) is written into settings and pinned as a driver; admin-required items get a button; BIOS-only items come with instructions.
Drivers · compatibility patches
Some machines only run after changing launch parameters (old GPUs with low GLES, no hardware acceleration, a driver version that crashes on hardware rendering). A driver is a JSON file: it declares "which machines it matches" + "which launch parameters to change on match". Write your own, import or share them. Drivers only change whitelisted launch items and execute no code; without a match they do nothing.
Reading drivers…
"Export this machine's template" fills the match conditions for this machine; edit gpuMode / forceTcg in effect and it is ready to use. Field docs are in docs/drivers.md in the repository.
